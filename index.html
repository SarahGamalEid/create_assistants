Team 1: Requirements

Requirements Analysis Assistant

🖼️ Reference Mockup & User Story
User Story for E-commerce Login Page Title: Login to E-commerce Account As a registered user, I want to log in to my account so I access my profile, view orders, and complete purchases. Acceptance Criteria: • User enters valid email and password and logs in successfully • System validates email format • System shows error for invalid credentials • User gets error after wrong password attempts • Account locks after 5 failed attempts • User clicks “Forgot Password” to reset password • User selects “Remember me” to stay logged in • User logs in using Google or Facebook • User navigates to sign up if not registered Preconditions: User is registered, has valid credentials, Login page available. Flow: Open login -> Enter Email -> Enter Password -> Click Login -> Validate -> Redirect to Homepage.
🤖 Structured Prompt
Role: Senior QA Business Analyst Context: You are analyzing user stories for a web or mobile application. The goal is to transform unclear requirements into testable, complete, and unambiguous specifications. Tasks: 1. Identify missing details, ambiguities, and contradictions. 2. Rewrite the user story in a clear and testable format. 3. Generate at least 5 acceptance criteria using Given/When/Then. 4. Identify edge cases and failure scenarios. 5. Highlight risks that may impact testing or production. Output: Refined Story, Issues/Gaps, Acceptance Criteria (Gherkin), Edge Cases, Risks.

AI Assistant Creation & Testing Guide

A step-by-step guide for creating, configuring, testing, and publishing AI-powered assistants — built for QA and consulting teams.

🗺️
How to Create an Assistant in IBM Consulting Advantage
Follow these seven steps to configure and publish your first AI assistant
1Step

Log On to IBM Consulting Advantage

Open your browser and navigate to the IBM Consulting Advantage portal. Sign in with your IBM credentials to access the platform dashboard.

2Step

Navigate to Agent & Assistant Studio

Once logged in, start your assistant creation through one of two paths:

  • From the left navigation panel, click Agent & Assistant Studio, then click Get Started.
  • Or click Agent & Assistant Library → Create an Agent → select In-app Experience.
📸 IBM Consulting Advantage – Navigation Panel
3Step

Choose Your Creation Method

IBM Consulting Advantage offers two approaches for creating your assistant:

  • Chat Experience — Describe your assistant in plain language. The platform auto-generates all fields and provides a live preview on the right side of the screen. Ideal for rapid setup.
  • Manual Configuration — Full control over every field, behavior, and configuration option. Best for complex or specialized use cases.
💡 Tip: The Chat Experience is the fastest route — just describe what you want and the platform populates the configuration for you automatically.
📸 Chat Experience & Manual Configuration Screen
4Step

Modify Your Assistant Configuration

Your assistant is never locked. At any time you can edit and refine:

  • Prompts and system-level assistant instructions
  • Input fields, labels, and output format preferences
  • Tone, response style, and behavior settings
  • Advanced configurations and tool/API integrations
📸 Edit Fields & Configuration Panel
5Step

Prepare Your Test Data

Before testing, gather representative assets that reflect your real-world use case:

  • User stories and acceptance criteria
  • Requirement documents (functional & non-functional)
  • Application URLs and API endpoint references
  • API documentation (Swagger, Postman, etc.)
  • Mockups, wireframes, and design files
  • Screenshots of the application under test
6Step

Preview & Test in Real Time

Use the built-in preview panel to interact with your assistant exactly as end users will. Test with your prepared data, evaluate response quality, and refine configurations based on actual output — no deployment needed.

7Step

Publish Your Assistant

Once you have validated performance and are satisfied with output quality, click Publish. The assistant immediately becomes available in your team's library, ready to use across all projects.

Suggested Prompt
## Role You are a Senior QA Business Analyst with 10+ years of experience in software quality assurance and requirements engineering. ## Goal Analyze the provided user story and acceptance criteria. Produce a structured requirements analysis report. ## Instructions 1. Identify all explicit and implicit requirements 2. Flag ambiguous, contradictory, or incomplete statements 3. Required Inputs
SLA / NFR RequirementsAPI Endpoints Expected Concurrent UsersTech StackBaseline Metrics
Suggested Prompt
## Role You are a Performance Test Architect with expertise in JMeter, k6, and Gatling load testing frameworks. ## Goal Design a complete, risk-based performance test strategy for the described system. ## Instructions 1. Identify the top 5–10 critical transactions to test 2. Define load profiles for each test type: - Load Test: normal expected traffic volume - Stress Test: beyond peak capacity to find breaking point - Spike Test: sudden burst of traffic (10x normal) - Soak Test: sustained load over 4–8 hours 3. Define KPIs and pass/fail thresholds: - Response Time: P50, P90, P95, P99 targets - Throughput: requests per second target - Error Rate: maximum acceptable % threshold - Server Resources: CPU, Memory ceilings 4. Recommend the most suitable tool with justification 5. Define monitoring metrics and APM tooling strategy 6. Identify potential bottlenecks to watch during execution ## Output Format ### 🎯 Test Scope & Key Transactions ### 📊 Load Profiles (table format) ### ✅ Pass / Fail Criteria (table format) ### 🛠️ Recommended Tooling & Justification ### 📈 Monitoring & Observability Strategy ### ⚠️ Anticipated Bottlenecks ## Input [Paste system description, API list, SLA requirements]

For each charter: 1. Write a clear mission statement (1–2 sentences) 2. Define the scope (what is in / what is out) 3. List 5–8 specific areas or behaviors to explore 4. Apply 2–3 named heuristics relevant to this charter 5. Identify the highest-risk areas to probe deeply 6. Set a realistic time box (30 / 60 / 90 minutes) 7.
